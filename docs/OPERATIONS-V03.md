# Operations v0.3
Run the same idempotent schema migration on the dedicated database. Operator console /operator requires a configured private bearer token. Create real slots from verified staff availability; overlapping slots are rejected, and reservation uses a database row lock and unique constraint. /booking displays only future unreserved slots. A stored confirmation is not an emailed invitation; calendar sync, cancellation and abuse prevention remain to be implemented.
Issue a seven-day client access token only after verifying the recipient. Share securely; raw tokens are returned once, not stored in the database. Tokens can be revoked by client. /portal scopes each query to the authenticated lead ID; proposal acceptance is recorded without charging. This is an initial private access design, not full production identity/RBAC. Add email verification, session rotation, MFA for staff, rate limiting, document storage, support, agreements, invoice generation and security integration tests before claiming complete portal readiness.
Operator console includes CRM stage changes, candidate partners, project creation, appointment publishing, portal issuance/revocation and proposal creation. No sample customers, fake appointments or partner agreements are seeded.
