# Runtime acceptance suite
CI uses an ephemeral PostgreSQL 16 service and a fixture seller, with commerce explicitly disabled. Test records are synthetic fixtures confined to the temporary CI database, never counted as prospects, clients, invoices or revenue. Runtime test verifies health, authentication, invalid intake, durable enquiries, overlapping slot refusal, atomic competing reservation, client-scoped proposals, cross-client acceptance denial, invoice cap, invoice isolation, checkout disabled without live provider configuration, revocation and nine public/internal route HTTP responses. This does not test browser rendering, actual provider payment, cancellation, refunds, production database backups, staff MFA or legal invoice validity. Record CI run and conclusion before merging.
