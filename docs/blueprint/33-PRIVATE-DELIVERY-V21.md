# Private delivery V2.1
New API: GET /api/client-files lists metadata or downloads a file by id; POST multipart uploads PDF/PNG/JPEG/UTF-8 text. Client scope derived exclusively from existing portal token, operator must select lead. Content signature and size checked; 2 MiB each, 12 MiB per lead and 64 MiB across the service. Transaction serializes storage cap and writes audit event. SHA-256 verified on download; forced attachment/no-store/nosniff. Files reside in the dedicated PostgreSQL database, not in the public repository or external shared bucket. No public share links.
This is a bounded early-stage document exchange, not a compliance-certified document vault; signature checks are not malware scanning. Do not use for identity docs, credentials, regulated or sensitive financial records. Future upgrade: private object storage, AV scanning, retention workflow, staff MFA, scoped staff roles, versioning and backups. Existing text document workflow preserved.
Tests: valid upload/download, cross-client scope, mismatched signature, unauthorized paths; isolated fixtures only.
